# Tail Call Optimization

Deep recursion in JavaScript usually ends with a `RangeError` and the familiar "maximum call stack size exceeded" message. Each function call needs a stack frame that remembers where to return, and engines keep only a limited number of them. **Tail call optimization** (TCO) is a compiler feature that discards that frame when the recursive call is the very last action a function performs. Instead of stacking a new frame, the engine reuses the current one, so a properly written tail-recursive function can run for millions of iterations without growing the stack.

## What makes a call a tail call

A call is in *tail position* when its result is returned directly, with no work left to do afterwards. In `return n + sum(n - 1)`, the addition happens after the inner call returns, so the frame must stay alive and optimization cannot apply. In `return sum(n - 1, acc + n)`, the recursive call is the final operation and its value is passed straight back. An accumulator parameter carries the running result forward, which is what makes the reuse possible.

Support is inconsistent across engines. Safari implements tail call optimization, while most others have chosen not to, citing debugging and stack-trace concerns. Code must therefore stay correct without it. The demo below detects support and compares a non-tail sum with a tail-recursive one.

## Recursive loops in practice

A tail-recursive function is essentially a `while` loop expressed with parameters. That makes it elegant for walks over lists or trees, but an explicit loop is always the portable choice when depth is unknown. Use tail recursion where it reads well, keep the accumulator explicit, and never depend on the engine optimizing it.

        "use strict";
