# Method Chaining

Method chaining is the practice of calling several methods in a row on the same object, with each call feeding into the next. The trick behind it is simple: every mutating method returns the instance it was called on, so the result becomes the receiver of the following call.

## Return the instance

A normal setter might return nothing, leaving you to repeat the variable name on every line. If instead the method ends with `return this;`, the expression evaluates to the object again. Calls can then be strung together without storing intermediate results.

The same reasoning applies to constructors and factory functions. As long as each step hands back an object with the remaining methods, the chain keeps working. A terminal method such as `describe()` or `build()` returns a final value instead and ends the sequence.

## Designing a readable chain

Fluent interfaces read best when each method name describes one small action and the order mirrors real steps. Short verbs work well: `add`, `mix`, `pour`, `serve`. Keep side effects predictable, and avoid returning a different type halfway through unless a new stage is genuinely intended.

One caution: because every step operates on shared state, a half-built object is still a valid object. If a chain can fail, decide whether to reset, throw, or leave the partial state visible, and document that choice.

Chains are also easy to extend. Adding a new step means writing one more method that returns `this`, with no change to the existing methods or to callers that ignore it. That openness is a real advantage for builder objects that grow alongside the application using them.

<script>
  class Smoothie {
    constructor() {
      this.fruits = [];
      this.seconds = 0;
      this.size = "medium";
    }
    add(fruit) { this.fruits.push(fruit); return this; }
    blast(seconds) { this.seconds += seconds; return this; }
    pour(size) { this.size = size; return this; }
    describe() {
      return this.size + " cup of " + this.fruits.join(" + ") + ", blended " + this.seconds + " seconds";
    }
  }

  var cup = document.getElementById("cup");
  var out = document.getElementById("out");

  function serve(builder, code) {
    cup.textContent = builder.describe();
    out.textContent = code + "\n\nResult: " + builder.describe();
  }

  document.getElementById("berry").addEventListener("click", function () {
    serve(
      new Smoothie().add("strawberry").add("blueberry").blast(20).pour("small"),
      "new Smoothie().add('strawberry').add('blueberry').blast(20).pour('small')"
    );
  });

  document.getElementById("tropical").addEventListener("click", function () {
    serve(
      new Smoothie().add("mango").add("pineapple").add("lime").blast(35).pour("large"),
      "new Smoothie().add('mango').add('pineapple').add('lime').blast(35).pour('large')"
    );
  });

  document.getElementById("identity").addEventListener("click", function () {
    var builder = new Smoothie();
    var returned = builder.add("pear");
    out.textContent = "builder.add('pear') === builder  ->  " + (returned === builder)
      + "\nThat identity is what makes the chain possible.";
    cup.textContent = "Same object, ready for more steps.";
  });
</script>
