# Promises

A promise is an object that stands in for a value which will arrive later. It begins in a pending state, then settles exactly once: either it is fulfilled with a value, or it is rejected with a reason. Promises give asynchronous code a readable shape. Instead of passing callbacks into callbacks, you attach handlers with `.then()` and `.catch()` and let the result flow forward.

## Creating and chaining

You build a promise with the `Promise` constructor. Its executor receives two functions, usually called `resolve` and `reject`, and you call one of them when the work completes. Because `.then()` returns a *new* promise, you can chain steps one after another. Returning a plain value from a handler passes it to the next handler; returning another promise makes the chain wait for that promise before continuing. This is how a sequence of dependent network requests stays flat instead of nesting.

```js
new Promise(function (resolve, reject) {
  setTimeout(function () { resolve("done"); }, 100);
}).then(function (msg) {
  return msg.toUpperCase();
}).then(console.log); // "DONE"
```

## Combining and cleaning up

Several helpers coordinate multiple promises. `Promise.all()` fulfills when every input fulfills, but rejects as soon as any one rejects. `Promise.race()` settles with whichever promise finishes first, which is useful for timeouts. `Promise.any()` fulfills with the first successful result, and `Promise.allSettled()` waits for everything and reports each outcome. The `finally()` method runs regardless of the result, making it the natural place to hide a loading indicator.

Most modern code reaches for `async` and `await`, which are built on promises. Awaiting an expression pauses the surrounding `async` function until the promise settles, without freezing the page.

      }

    <script>
      var out = document.getElementById("out");
      function log(msg, cls) {
        var line = document.createElement("div");
        line.textContent = msg;
        if (cls) line.className = cls;
        out.appendChild(line);
      }
      function fakeFetch(name, ms, value) {
        return new Promise(function (resolve, reject) {
          setTimeout(function () {
            if (value === null) reject(new Error(name + " failed"));
            else resolve(value);
          }, ms);
        });
      }
      function jobs() {
        return [
          fakeFetch("users", 300, "12 users"),
          fakeFetch("orders", 650, "5 orders"),
          fakeFetch("stats", 150, "98% uptime")
        ];
      }
      document.getElementById("chain").onclick = function () {
        log("> starting sequential chain");
        jobs().reduce(function (chain, p) {
          return chain.then(function () { return p; }).then(function (v) {
            log("  got " + v, "ok");
          });
        }, Promise.resolve()).then(function () {
          log("chain complete", "ok");
        });
      };
      document.getElementById("all").onclick = function () {
        log("> starting Promise.all()", "");
        Promise.all(jobs()).then(function (results) {
          log("all settled: " + results.join(", "), "ok");
        }).catch(function (e) {
          log("error: " + e.message, "err");
        });
      };
      document.getElementById("clear").onclick = function () { out.textContent = ""; };
    </script>
  </body>

The chained version logs results one at a time as each timer fires, while `Promise.all()` waits for the slowest request before printing a single summary line.
