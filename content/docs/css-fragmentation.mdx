# Fragmentation

Fragmentation is the layout process that flows one stream of content into several boxes — printed pages, newspaper columns, or regions. The browser decides where the breaks fall, and it usually decides badly: a heading stranded at the bottom of a page, a table row sliced in half, a card split across a fold.

Three properties give you a veto.

## The break properties

- `break-before` — force or forbid a break above the box.
- `break-after` — force or forbid a break below the box.
- `break-inside` — control splitting within the box.

Values worth knowing: `auto` lets the browser choose, `avoid` discourages a break, `page` forces a page break, and `column` forces a column break. For paged media you also get `left` and `right`, which start on a specific side of a spread — useful for chapter openers. `avoid-page` and `avoid-column` narrow the instruction to one context.

Older code uses `page-break-before`, `page-break-after`, and `page-break-inside` with values `always` and `avoid`. Those are legacy aliases; keep them alongside the modern properties if you still support very old engines.

Two more knobs help with prose: `orphans` sets the minimum lines left at the bottom of a page, and `widows` sets the minimum lines carried to the top of the next one. A value of `3` for both is a sane default for body text.

## A practical recipe

The rules that solve most report layouts:

- Headings: `break-after: avoid`, so a heading never ends a page alone.
- Cards, blockquotes, and figures: `break-inside: avoid`.
- Table rows: `break-inside: avoid`, plus `thead { display: table-header-group }` so the header repeats.
- Major sections: `break-before: page`.

`break-inside: avoid` is a request, not a guarantee. If a box is taller than a page, the browser has to split it anyway, so keep the units you protect page-sized or smaller.

```html
<style>
  * { box-sizing: border-box; }
  body {
    margin: 0;
    padding: 26px 18px;
    background: linear-gradient(180deg, #eef1f6, #e3e8f1);
    font-family: ui-sans-serif, system-ui, -apple-system, sans-serif;
    color: #23324a;
  }
  .doc { width: min(620px, 94vw); margin: 0 auto; display: grid; gap: 20px; }
  .sheet {
    padding: 26px 28px 30px;
    background: #ffffff;
    border-radius: 10px;
    box-shadow: 0 22px 40px -30px rgba(25, 40, 70, 0.8);
  }
  .sheet h2 {
    margin: 0 0 4px;
    font-size: 1.15rem;
    color: #1b3a63;
    break-after: avoid;
    page-break-after: avoid;
  }
  .sheet p { margin: 0 0 14px; line-height: 1.65; font-size: 0.92rem; }
  .kicker {
    margin: 0 0 10px;
    font-size: 0.7rem;
    letter-spacing: 0.14em;
    text-transform: uppercase;
    color: #7c8ba5;
  }
  .card {
    margin-top: 16px;
    padding: 16px 18px;
    background: #f3f7ff;
    border-left: 4px solid #4a7ad1;
    border-radius: 8px;
    break-inside: avoid;
    page-break-inside: avoid;
  }
  .card strong { display: block; color: #1b3a63; font-size: 0.9rem; }
  .card span { font-size: 0.82rem; color: #566a88; }
  .part {
    margin-top: 4px;
    border-top: 2px dashed #c8d4e7;
    padding-top: 18px;
    break-before: page;
    page-break-before: always;
  }
  .tag {
    display: inline-block;
    padding: 3px 9px;
    border-radius: 999px;
    background: #e7eefc;
    color: #3a5d94;
    font-size: 0.68rem;
    letter-spacing: 0.08em;
    text-transform: uppercase;
    white-space: nowrap;
  }
  .hint {
    margin: 0;
    text-align: center;
    font-size: 0.72rem;
    letter-spacing: 0.08em;
    text-transform: uppercase;
    color: #7c8ba5;
  }
  @media print {
    body { background: #fff; padding: 0; }
    .doc { display: block; width: auto; }
    .sheet { box-shadow: none; border-radius: 0; padding: 0; }
    .sheet + .sheet { margin-top: 0; }
    .hint { display: none; }
  }
</style>

<article class="doc">
  <section class="sheet">
    <p class="kicker">Quarterly review · page 1</p>
    <h2>What changed this quarter</h2>
    <p>
      Fragmentation rules matter most where content is generated: dashboards that export to PDF,
      invoices, and long editorial pages. A single stray break can orphan a heading or slice a
      summary card in half.
    </p>
    <div class="card">
      <strong>This card is kept whole <span class="tag">break-inside: avoid</span></strong>
      <span>The browser will push the entire block to the next page rather than split it.</span>
    </div>
    <p style="margin-top:16px">
      The next section starts on a fresh page in print, and is separated by a rule on screen.
    </p>
  </section>

  <section class="sheet part">
    <p class="kicker">Quarterly review · page 2</p>

      Body copy keeps the default, letting paragraphs split between lines.
    </p>
    <div class="card">
      <strong>Test with a real print preview <span class="tag">@media print</span></strong>

  </section>
</article>
```

Print styles need testing in an actual print preview, not just a screenshot. Chrome's "Save as PDF" and Firefox's print dialog are the two engines worth checking before you ship an invoice template.
