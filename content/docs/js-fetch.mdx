# Fetch

`fetch()` is the modern way to make network requests in the browser. It returns a promise that resolves to a `Response` object, replacing the older callback-based `XMLHttpRequest`. Because it is promise-based, it works nicely with `async` and `await`.

## The basics of fetch

The simplest call takes a URL and returns a promise:

```js
fetch('/api/users')
  .then(function(response){
    if (!response.ok) throw new Error('Request failed');
    return response.json();
  })
  .then(function(data){ console.log(data); })
  .catch(function(err){ console.error(err); });
```

A resolved promise does not mean the request succeeded. A 404 or 500 still resolves; you must check `response.ok` or `response.status` yourself. Note also that `fetch()` only rejects on network failure, not on HTTP error statuses.

## Reading response bodies

The `Response` object offers several readers, each returning a promise: `json()` for JSON, `text()` for plain text, `blob()` for binary data, and `arrayBuffer()` for raw bytes. You can call only one of them, because a response body can be consumed a single time. `response.headers` exposes the returned headers.

## Headers, POST data, and credentials

For a POST request, pass a second argument with a `method`, `headers`, and a serialized `body`:

```js
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Ada' })
});
```

Cookies are not sent to other origins by default. Set `credentials: 'include'` when you need them, and remember the server must also allow that origin. Browser security rules still apply, so the target must permit cross-origin requests.
