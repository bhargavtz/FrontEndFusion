# Symbols

A symbol is a primitive value that is guaranteed to be unique. Each call to `Symbol()` produces a value that cannot equal any other symbol, even when both are created with the same description. That makes symbols ideal as property keys when you want to avoid collisions with code you do not control, such as a library adding metadata to your objects.

## The symbol primitive

Symbols are created by calling `Symbol`, optionally with a description used only for debugging. They can be used as object keys with computed property syntax or added after creation. Symbol-keyed properties are intentionally skipped by `Object.keys` and `for...in`, so they behave like hidden fields. To list them you must ask for `Object.getOwnPropertySymbols` or use `Reflect.ownKeys`.

Because symbols are not automatically converted to strings, trying to concatenate one with a string throws a `TypeError`. Use `String(symbol)` or the `symbol.description` property when you need a readable form.

## The global symbol registry

Sometimes two independent pieces of code need to share the *same* symbol. `Symbol.for(key)` looks up a symbol in a global registry and reuses it if present, or creates it if not. Calling `Symbol.for("id")` twice returns the identical value, unlike two calls to `Symbol("id")`. You can reverse the lookup with `Symbol.keyFor`, which returns the registry key or `undefined`.

Well-known symbols such as `Symbol.iterator` and `Symbol.toPrimitive` are built into the language and let your objects participate in core behaviours like iteration and coercion.
