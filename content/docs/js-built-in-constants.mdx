# Built-in Constants

JavaScript has a handful of values that are not ordinary numbers or strings. They appear whenever a calculation fails, a value is missing, or a number grows beyond what the format can hold. Recognising them saves a lot of confused debugging.

## null and undefined

`undefined` means a variable has been declared but never given a value, or a function returned nothing. `null` is an intentional empty value that you assign yourself. They are loosely equal to each other but not strictly equal, so `null == undefined` is true while `null === undefined` is false. To test for either at once, use `value == null`.

## NaN and isNaN

`NaN` stands for "Not a Number" and is the result of an invalid numeric operation, such as subtracting a word from a number. It is sticky: once a calculation produces `NaN`, almost anything you do with it stays `NaN`. It is also the only value that is not equal to itself, so testing with `==` or `===` never works. Use `Number.isNaN()` or the older global `isNaN()` instead.

Some operations that produce it include dividing zero by zero, multiplying a number by a non-numeric string, and parsing an empty string. Several Math functions return it too, for example `Math.sqrt(-1)` and `Math.acos(2)`.

## Infinity and the Number constants

Dividing a positive number by zero gives `Infinity`, and dividing by negative zero gives `-Infinity`. They behave like mathematical infinity in comparisons, so any finite number is smaller than `Infinity`.

The `Number` object carries useful constants: `Number.MAX_VALUE`, `Number.MIN_VALUE`, `Number.MAX_SAFE_INTEGER`, and `Number.NaN`. The safe-integer limit matters because beyond it some whole numbers cannot be represented exactly.
