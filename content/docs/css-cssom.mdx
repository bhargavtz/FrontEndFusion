# CSS Object Model (CSSOM)

The CSSOM is the browser's live, scriptable representation of every style rule on the page. CSS text is parsed into objects: a stylesheet owns an ordered list of rules, each rule owns a declaration block, and each declaration is a property-value pair you can read or change without touching the markup.

## Two ways to read a style

`element.style` exposes only the inline declarations on that element. It is a `CSSStyleDeclaration` and it is writable:

```css
panel.style.background = "#4f7cff";
panel.style.setProperty("--accent", "#4f7cff");
```

`getComputedStyle(element)` returns the resolved values after the cascade — inherited properties, relative units turned into pixels, and browser defaults all included. It is read-only, and the object updates live as styles change:

```css
const padding = getComputedStyle(panel).paddingTop; // "24px"
```

Use `element.style` when you are setting a value and `getComputedStyle` when you need to know what actually won. Reading `element.style.width` after a stylesheet sets the width returns an empty string, which is a common source of bugs.

## Style sheets and cssRules

`document.styleSheets` is an array-like list of every sheet applied to the document, including `link`ed files and inline `style` blocks. Each sheet exposes `cssRules`, an ordered collection where index matters: later rules with equal specificity win. A sheet loaded from another origin throws a security error when you touch `cssRules`, so you cannot inspect a third-party stylesheet.

The mutating API is small:

- `sheet.insertRule(".badge { opacity: .8 }", index)` — add a rule at a position.
- `sheet.deleteRule(index)` — remove one.
- `rule.style.setProperty("background", value)` — change a declaration inside an existing rule.
- `new CSSStyleSheet()` with `replaceSync(text)` — build a sheet in memory and adopt it, the basis of constructable stylesheets for web components.

Editing a rule beats writing inline styles when one change should affect many elements. One `cssRules` edit repaints every match and keeps the DOM clean.

```html

</style>

  <p>Each button rewrites the same declaration inside a style sheet, then asks <code>getComputedStyle</code> what the browser resolved.</p>

<script>
  const sheet = document.getElementById("theme").sheet;
  const rule = sheet.cssRules[0];
  const badge = document.getElementById("badge");
  const readout = document.getElementById("readout");
  let glowIndex = -1;

  function report() {
    const computed = getComputedStyle(badge);
    readout.textContent =
      "cssRules: " + sheet.cssRules.length +
      " | background: " + computed.backgroundColor +
      " | box-shadow: " + (computed.boxShadow === "none" ? "none" : "set");
  }

  document.querySelectorAll("[data-color]").forEach((button) => {
    button.addEventListener("click", () => {
      rule.style.background = button.dataset.color;
      report();
    });
  });

  document.getElementById("glow").addEventListener("click", () => {
    if (glowIndex === -1) {
      glowIndex = sheet.insertRule(
        ".badge { box-shadow: 0 0 0 8px rgba(79, 124, 255, 0.22); }",
        sheet.cssRules.length
      );
    } else {
      sheet.deleteRule(glowIndex);
      glowIndex = -1;
    }
    report();
  });

  report();
</script>
```

If that glow rule never appears in the computed style, check the index you passed to `insertRule` — inserting before an earlier rule with equal specificity can make the new one lose the cascade.
