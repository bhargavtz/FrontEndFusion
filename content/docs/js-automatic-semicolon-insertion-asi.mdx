# Automatic Semicolon Insertion - ASI

JavaScript does not strictly require semicolons. When a statement is missing one, the parser inserts it automatically in certain situations. This feature, called automatic semicolon insertion, is convenient but can produce surprising results if you rely on it without understanding the rules.

## Rules of insertion

The engine inserts a semicolon when it meets a token it cannot parse, provided that token is separated from the previous one by at least one line break. It also inserts one at the end of a line that is clearly complete, and at the end of the input. A crucial detail is that the line break matters: without one, the tokens usually combine into a single expression instead of two statements.

Statements most affected include `return`, `throw`, `break`, `continue`, variable declarations, and expression statements. The classic trap is starting a new line with `(` or `[` after a statement, because the parser treats it as a continuation such as a function call or property access.

## Never break after return

When a `return` statement is followed by a line break, a semicolon is inserted immediately after `return`. Any expression on the next line is unreachable. Returning an object literal on the following line therefore returns `undefined`, because the braces are parsed as a block rather than an object. Keeping the value on the same line as `return`, or wrapping it in parentheses, avoids the bug.

Many teams adopt a style guide that either always writes explicit semicolons or deliberately omits them but guards the risky cases. Either choice is fine as long as it is consistent and a linter enforces it.
