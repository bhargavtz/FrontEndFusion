# Variable coercion/conversion

JavaScript is a loosely typed language, so values are often converted automatically when operators expect a different type. Understanding these rules, known as coercion, explains many surprising results and helps you write clearer comparisons.

## Implicit conversion and truthiness

When an operator mixes types, the engine converts one operand to match the other. Adding a string and a number concatenates them, while subtracting coerces both to numbers. In a boolean context, values become either truthy or falsy. The falsy values are `false`, `0`, an empty string, `null`, `undefined`, and `NaN`. Everything else, including empty arrays and objects, is truthy. Applying the logical NOT twice, written as two exclamation marks before a value, is a compact way to force any value into a true boolean.

## Explicit conversions

You can control conversion instead of relying on it. `Number()` and `parseFloat()` turn strings into numbers, though the parser is stricter than the constructor about trailing characters. `String()` produces a textual form, and `Boolean()` forces truthiness. Unary plus is a short alternative to `Number()`. Converting a number to an integer can be done with `Math.trunc()`, `Math.floor()`, or `parseInt()` depending on how negatives should behave.

## Equality quirks and arrays

The loose equality operator converts types before comparing, so a string of digits can equal the matching number. The strict operator compares both value and type and avoids that surprise; prefer it in new code. Arrays coerce to strings by joining their elements with commas, which is why an empty array becomes an empty string and a single-element array becomes that element. Calling `map()` or `join()` explicitly is usually clearer than depending on this behaviour.
