# Colors

CSS accepts a colour in several notations, and they all resolve to the same underlying value. The differences are about readability, precision, and how easily you can derive related shades. Picking the right notation makes a palette easier to maintain.

## Keywords, hex, and rgb()

The 148 named keywords — `tomato`, `rebeccapurple`, `steelblue` — are convenient for quick tests and demos, but they carry no design intent and are hard to search for later. Use them sparingly in production.

Hex is the compact workhorse: `#2f6f8f`, or the shorthand `#28f` when each pair repeats. Three-, four-, six-, and eight-digit forms exist; the four- and eight-digit versions finish with an alpha channel. Hex is opaque to humans scanning a stylesheet — you cannot tell at a glance how light or saturated it is.

`rgb()` is explicit and works well with computed values: `rgb(47 111 143)`, with an optional fourth value for alpha (`rgb(47 111 143 / .5)`). Legacy comma syntax still works, and `rgba()` remains a valid alias.

## HSL and alpha

`hsl()` describes a colour the way a designer thinks about it: hue in degrees, saturation and lightness in percentages. Because those axes are independent, generating a palette is straightforward — hold the hue, shift lightness for hover and active states, or adjust saturation for muted variants. `hsl(202 51% 37%)` is the same blue as the hex above, and `hsl(202 51% 37% / .35)` adds transparency.

Alpha transparency is not the same as `opacity`. An alpha colour affects only that one value, so a background can be translucent while its text stays fully solid. `opacity` fades the entire element, children included.

## currentColor

`currentColor` resolves to the element's computed `color`. It is the cleanest way to keep decorative borders, icons, and SVG fills in sync with text: set `color` once, then use `border-color: currentColor` or `fill="currentColor"` elsewhere. Change the text colour on hover and every dependent detail follows automatically.
