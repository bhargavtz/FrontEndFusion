# Positioning

The `position` property changes how an element is placed and what it is positioned against. Normal flow is the default; the other values let you pull an element out of that flow or pin it to the viewport.

## The five values

`static` is the default. Offsets do nothing, and the element simply follows the document order.

`relative` keeps the element in flow but shifts its painted box by `top`, `right`, `bottom`, or `left`. The space it originally occupied stays reserved, so neighbours do not move. More importantly, a relatively positioned element becomes the containing block for absolutely positioned descendants.

`absolute` removes the element from flow and places it against the nearest positioned ancestor — or the initial containing block if there is none. This is the standard tool for badges, close buttons, dropdown panels, and image captions. Forgetting the ancestor is the most common bug: the element escapes to the page corner.

`fixed` also leaves flow, but it anchors to the viewport. It stays put while the page scrolls, which suits floating action buttons and modal backdrops. Note that a transformed ancestor can become the containing block, breaking the effect.

`sticky` is a hybrid. The element behaves normally until a scroll threshold is crossed, then it sticks within its containing block. It needs an offset such as `top: 0`, and it stops sticking once its parent scrolls away.

## z-index and stacking

`z-index` only applies to positioned elements (and flex or grid items). Higher numbers paint on top, but only within the same stacking context. A parent with `transform`, `filter`, `opacity` below 1, or its own `z-index` creates a new context, so a child with `z-index: 9999` still cannot jump above a sibling context. Reach for small, local numbers rather than escalating a z-index war.
