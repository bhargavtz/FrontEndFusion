# Datatypes in JavaScript

JavaScript values fall into a small set of types: primitives such as number, string, boolean, `undefined`, `null`, `symbol`, and `bigint`, plus the catch-all object type. Because variables are not declared with a type, you often need to ask what a value actually is at runtime.

## Checking types with typeof

The `typeof` operator returns a string naming the type. It is the first tool to reach for, but it has two famous quirks: `typeof null` returns `"object"`, and `typeof` an array also returns `"object"`. Functions return `"function"` even though they are objects underneath.

```js
typeof 42;        // "number"
typeof "hi";      // "string"
typeof [];        // "object"
typeof null;      // "object" (a historical quirk)
```

## Finding a class or constructor name

When `typeof` is too vague, `Object.prototype.toString.call(value)` returns a tag such as `"[object Array]"` or `"[object Date]"`. It distinguishes arrays, dates, regular expressions, and plain objects reliably, which makes it a favourite for type-checking utilities.

Every object also inherits a `constructor` property. Reading `value.constructor.name` gives the name of the function that built it, for example `"Array"` or `"Object"`. This is handy for a quick look, but it can be changed or missing on objects created without a prototype, so prefer the tag approach for serious validation. Remember that primitives can appear to have constructors too, because JavaScript briefly wraps them in an object when you read the property.

Taken together, these three techniques cover most situations: reach for `typeof` first, use the `Object.prototype.toString` tag when you need to tell objects apart, and glance at the constructor name when you only need a readable label.
