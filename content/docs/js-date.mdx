# Date

The `Date` object represents a single moment in time. Internally it stores the number of milliseconds since the Unix epoch, the first of January 1970 in UTC, and offers methods for reading or changing the calendar parts of that moment.

## Creating Date objects

Calling `new Date()` with no arguments creates an object for the current moment. You can also pass a date string, or several numbers such as year, month, and day. Months start at zero, so January is `0` and December is `11` — a detail that causes many off-by-one bugs. To build a date in UTC without local time-zone shifts, use `Date.UTC()` and pass the resulting number to the constructor.

## Reading and formatting parts

Getter methods extract pieces of the date: `getFullYear()`, `getMonth()`, `getDate()`, `getHours()`, `getMinutes()`, and `getDay()` for the weekday. Each has a UTC counterpart such as `getUTCHours()`.

For display, `toString()` produces a readable local string, while `toISOString()` returns a standard UTC string ending in `Z`. Because built-in formatting is limited, custom formatting usually means combining getters into your own layout, for example padding the month and day with a leading zero.

## Moving dates and converting

`getTime()` returns the millisecond timestamp, which makes arithmetic easy. To increment a date, call `setDate(getDate() + 1)`; the setters automatically roll over into the next month or year. `toJSON()` returns the same value as `toISOString()`, so dates serialise cleanly into JSON payloads.
