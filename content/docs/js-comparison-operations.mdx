# Comparison Operations

Comparisons are the decisions of a program. They decide which branch runs, whether a loop continues, and whether a value is valid. JavaScript has two families of equality plus a set of logical operators, and knowing how they coerce types will save you from surprising results.

## Equality: loose versus strict

Strict equality, `===`, compares both value and type and does no conversion. Loose equality, `==`, converts operands to a common type first, which leads to rules such as `null == undefined` being true while `null === undefined` is false, and `[] == false` being true because the empty array becomes an empty string and then zero. Prefer strict equality unless you deliberately want coercion.

`NaN` is special: it is not equal to anything, including itself. Use `Number.isNaN()` or `Object.is()` to detect it. `Object.is()` also distinguishes positive and negative zero, which `===` treats as equal. Inequality is the mirror image: `!=` and `!==` negate the corresponding equality check.

## Relational and logical operators

Relational operators include `<`, `<=`, `>`, and `>=`. When both operands are strings they compare lexicographically by character codes; otherwise JavaScript tries to convert them to numbers. The logical operators `&&`, `||`, and `!` work with booleans, but they also accept any value.

## Short-circuiting and coercion

The `&&` and `||` operators short-circuit: `&&` stops at the first falsy value, `||` at the first truthy one. Crucially, they return the operand itself, not a boolean. That makes patterns like `name || "Guest"` a compact fallback. Falsy values include `false`, `0`, an empty string, `null`, `undefined`, and `NaN`.

Grouping several statements with parentheses controls the order of evaluation. At a lower level, each boolean can be treated as a bit, allowing a small integer to pack several on-or-off flags — a technique called a bit field.
