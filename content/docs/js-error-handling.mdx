# Error Handling

Errors are values that describe something going wrong. Handling them deliberately keeps an application from failing silently or crashing at the first unexpected input. JavaScript uses exceptions for synchronous failures and rejected promises for asynchronous ones.

## Error objects and built-in types

Throwing creates an `Error` object with a `message` and a `stack` trace. JavaScript also provides specialized constructors: `TypeError` for a value of the wrong kind, `ReferenceError` for an undeclared name, `RangeError` for a value outside the allowed range, `SyntaxError` for invalid code, and `URIError` for a bad encoded URL. You can define your own error type by extending `Error`, which lets callers distinguish expected application errors from genuine bugs.

A `try` block wraps risky work; `catch` receives the thrown value; `finally` always runs, which makes it the right place to release resources. Catch sparingly: wrapping everything hides bugs. Catch where you can actually recover or add useful context.

## Errors and promises

Inside an `async` function, a thrown exception becomes a rejected promise, so `try`/`catch` works across an `await`. With raw promises, use `.catch()` at the end of the chain. An important detail is ordering: `.catch()` only handles rejections that happen *before* it in the chain, so placement changes behavior. Also remember that a `throw` inside a `.then()` is captured as a rejection, while a `throw` inside a `setTimeout` callback is not — that one escapes to the global handler.
