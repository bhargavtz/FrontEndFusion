# Scope

Scope decides where a name is visible in your program. JavaScript has global scope, function scope, and, since ES6, block scope. Getting it right prevents bugs where a variable is read before it exists or leaks out of the block that created it.

## Block scope and var versus let

Variables declared with `let` and `const` live only inside the nearest pair of curly braces. A `var` declaration ignores blocks and belongs to the whole enclosing function. That is why a `var` declared in a loop can be seen after the loop, while a `let` cannot. Prefer `let` and `const` by default; reach for `var` only when maintaining older code.

```js
if (true) {
  let blockOnly = 1;  // gone outside this block
  var leaksOut = 2;   // visible in the whole function
}
```

## Hoisting

Declarations are processed before code runs, a behaviour called hoisting. Function declarations are fully available early, but `var` variables are created with the value `undefined` until their assignment executes. `let` and `const` are also hoisted to the top of the block, yet they sit in a temporary dead zone: touching them before the declaration throws an error. This is another reason to declare values near where you use them.

## Closures

A function remembers the scope it was created in, even after that outer function has returned. This combination is called a closure. It is the basis of private state: a variable inside the outer function cannot be reached from outside, but any inner function can still read and change it. Factories that return counter functions, event handlers that capture an index, and modules that hide helpers all rely on closures.

The demo creates two counters from one factory. Each one closes over its own independent `count`, so updating one never touches the other. A short panel also shows the classic hoisting surprise.
